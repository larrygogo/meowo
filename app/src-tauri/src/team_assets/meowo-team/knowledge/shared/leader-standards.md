# 用户的标准从哪里读

用户的标准是他本人说过、跨项目都适用的品味和工作规矩。它们属于个人层，这个托管文件里不放任何条目，只说明去哪里读、怎么用。

## 读哪里

1. **品味清单**：`{{PERSONAL_DIR}}/config.json` 里 `taste` 字段给出的路径。它可以在用户自己的 git 仓库或网盘里，几个人也可以共用一份。没配 `taste` 时，看 `{{PERSONAL_DIR}}/taste.md` 在不在（`team-learn` 第一次记品味时会建它）。
   - 设计师读全文。
   - 开发重点读工程、与 AI 协作相关的部分。
   - 审查员读与 AI 协作相关的部分，以及和本次改动相关的条目。
   - 产品经理读产品相关的部分。
2. **用户的标准**：`{{PERSONAL_DIR}}/standards.md`。从具体项目里提炼出、但对所有项目都适用的规矩（体验、工程、协作）。所有角色都读。
3. **用户自己的全局指令**：Claude Code 用户级的 `CLAUDE.md`。它会自动加载，所有角色都要遵守；回复用什么语言也跟随它和项目的指令，团队文件不另做规定。

## 怎么用

- 用的是条目背后的原则，不是照搬例子里的具体做法。品味清单里的例子常来自某个具体项目，换了项目要先想清楚它在防什么。
- 优先级：项目层 > 用户的标准 > 托管的做法库和功底默认值。托管层标了「底线」的条目除外，冲突时在交付里说出来。
- **读不到时照常干活。** 文件不存在、路径不对、网盘没挂载，都不停下来问；在交付里写一句「没读到你的品味清单（或 standards.md），按通用标准做」，技术负责人会在结尾卡片里带给用户。

## 怎么往里加

只记用户本人说过的。由 `team-learn` 按层记：跨项目的品味写进品味清单，跨项目的工作规矩写进 `standards.md`，只对一个项目成立的写进项目 Lead 目录。不写进这个托管文件——升级会覆盖。

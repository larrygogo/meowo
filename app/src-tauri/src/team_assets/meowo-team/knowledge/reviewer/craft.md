# 测试/审查：专业功底（第 1 层）

目标是找出「目的达不成」的可复现原因，不是给实现打分。只认证据，不认说法。不改产品源码。

## 独立性

- [ ] 先读规格的目的、终态、验收判据和反例，再看实现；不先读实施者的进度和推理，避免被带偏。
- [ ] 自己跑验证，不复用实施者的截图和日志当证据；实施者的证据只用来对照。
- [ ] 每项结论写清：通过 / 失败 / 无法判定 / 只做了静态判断，以及在哪个提交上得出的。

## 走真实入口

- [ ] 用户怎么用就怎么验：页面在真实浏览器 / 真实窗口 / 真机里操作，接口用真实请求，定时任务用真实入口脚本和真实授权参数复现。只跑单元测试不算验证了功能。
- [ ] 平台特有的渲染（深色模式、圆角边缘、抽屉、动效、小字号）要在真实画面上看；截图按实际缩放看小字。
- [ ] 每种状态都走：空、有数据、出错、弹层打开；「选了」和「不选直接关」两条路都走。
- [ ] 旧数据、老版本客户端、并发、重复提交、中途重启这些边界至少挑相关的各试一次。

## 测试本身可不可信

- [ ] 变异检查：把被测的防线故意改坏（去掉校验、改回旧写法），测试必须失败；不失败说明测试是摆设。
- [ ] 桩不能掩盖真实行为：桩要按真实工具的限制校验参数（长度上限、必填项），测试数据用真实长度和格式；关键参数最后交给真实工具空跑（dry-run）校验。
- [ ] 测试用的「外部文件」「越界目标」要真的越界，不能恰好落在别的拦截名单里（否则测到的是别的规则）。
- [ ] 断言看实际效果（文件有没有生成、标记有没有出现），不靠从模型输出里 grep 关键字。
- [ ] 看断言之前先看测试数据：这组数据能不能让断言失败？（这条在防：目标数恰好是 1 时，「失败不计进度」的断言是空的，只有变异检查才发现得了）

## 权限与安全

- [ ] 授权按「最坏的人会怎么用」来想：相对路径能不能被同名文件冒充、可写目录里能不能放脚本、复合命令和 `bash -c` 能不能绕过、读权限能不能读到本机凭据和 `.env`。
- [ ] 脱敏靠逐条正则列举的，用没列过的写法补测；能不把敏感原文交给模型的，优先不交。
- [ ] 归属和权限校验要追到最终执行的那一层，并核对部署分支上的版本，不只看接口层或功能分支。
- [ ] 审查过程中不制造副作用：不发消息、不写真实数据、不改真实配置；测试会话关掉 hooks。万一产生了，在报告里如实列出。

## 报告

- [ ] 写到指定路径，以「## 总结论」结尾：通过几项、失败几项、无法判定几项。
- [ ] 每个问题：严重程度、复现步骤（命令或操作）、证据位置、影响、改法方向。
- [ ] 写「目标被打折」：实现有没有偷偷缩小规格里的野心。
- [ ] 写「未验证边界」和「工作树变化」：自己没测到什么、自己改动了什么。

# 开发：专业功底（第 1 层）

一个功能的前端、后端、数据从实现到自验做到底。下面是跨项目通用的自查清单，交付前逐条过；不适用的写「不适用」，不要跳过。

## 开工前

- [ ] 读项目约定：`CLAUDE.md` / `AGENTS.md`、Lead 目录的 `product.md`、Lead 目录的 `standards.md`、Lead 目录的 `team.md`、README 的开发一节。命令（装依赖、跑测试、类型检查、本地预览）以项目为准。
- [ ] 先跑一遍现有测试和类型检查，记下基线。改之前就失败的，单独记，不算到自己头上，也不顺手掩盖。
- [ ] 弄清这次改动碰到哪些层：界面、接口、数据、后台任务、配置、对外集成。每碰到一层，下面对应的清单都要过。
- [ ] 不清楚的业务事实先在代码和文档里查；查不到才问，问的时候给出推荐答案。

## 数据

- [ ] 改表结构用可回滚的迁移：先加后删（expand → 迁移数据 → contract），不在一个版本里改名又删列。
- [ ] 旧数据怎么办：已有的记录、已发布的配置、用户本地的存档都要有处理，写清楚。
- [ ] 不手动改生产数据，改数据走接口或迁移脚本。
- [ ] 删除和覆盖前先确认目标；能软删就不硬删。

## 接口与兼容

- [ ] 老版本客户端还在跑：新字段可选，旧字段不立刻删，行为变化有兼容路径。
- [ ] 归属和权限在服务端最终执行的那一层校验，不只在接口层或前端。
- [ ] 会重试的操作做成幂等（重复提交、网络重放、定时任务重跑）。
- [ ] 报错给用户「怎么办」，不只讲原因；内部细节不外泄；错误文字和实际发生的事一致（不要对所有情况都说同一句）。
- [ ] 涉及钱、积分、数据的路径（发放、扣减、自动入账、迁移）打结构化日志：谁、什么、多少、结果；交付里写怎么判断正常、怎么回滚。（这条在防：出了问题只有启动日志可看，既判断不了是否正常，也不知道怎么回滚）

## 界面

- [ ] 每种状态都做了：加载、空、有数据、出错、禁用、弹层打开；深浅两种模式。
- [ ] 会增删重排的列表用稳定 id 做 key；回调不要直接把事件处理器当带参函数传。
- [ ] 先出能看到的部分，慢的细节异步加载；不乱跳、不乱闪；生效要有明确动作。
- [ ] 平台控件：iOS 原生应用优先系统控件；桌面 WebView 里不用浏览器原生弹层（样式和应用不是一套）。
- [ ] 有设计稿时照设计稿做，偏离处说明理由；没有设计稿的界面改动，先找设计师。

## 安全

- [ ] 密钥不进代码、不进日志、不进提交；用环境变量或密钥管理。
- [ ] 外部输入（URL、文件、命令参数、SQL）做校验和转义；拼命令、拼 SQL 一律参数化。
- [ ] 给自动化或无人值守的流程授权时写绝对路径、最小权限。

## 验证

- [ ] 单元测试覆盖新逻辑；改坏它，测试要能失败（至少挑一处试一次）。
- [ ] 测试数据真的能走到被测分支：写断言前想一下「这组数据下，代码写错了断言会不会失败」（例如目标数恰好是 1 时「失败不计进度」的断言是空的）。（这条在防：断言看起来在测，其实改坏代码也照样通过）
- [ ] 测试结束清理自己建的临时目录和临时库。（这条在防：每跑一次测试留下一批临时目录，几轮审查下来堆出几百个）
- [ ] 前端的乐观更新（先改界面、失败回退）要有可重跑的自动测试，不只靠手点。
- [ ] 客户端用服务端快照覆盖本地状态时，按请求序号或状态版本丢弃过期响应；涉及两个请求交错的，两种到达顺序都测。（这条在防：只修了「新响应先到」，没测「旧响应后到」把刚改好的状态又改回去）
- [ ] 状态重置分支（跨天、登出、清理缓存）也有用例；变异检查要覆盖到「清理」类代码。
- [ ] 在真实入口跑一遍：页面在浏览器 / 真机 / 真实窗口里点过，接口用真实请求打过。拿不到真实环境就明说没验证什么。
- [ ] 界面改动截图（前后对比、深浅模式），自己先看一遍细节再交。
- [ ] 跑全部测试和类型检查，和开工前的基线对比。

## 提交与收尾

- [ ] PR 的拆法按项目约定；项目没说的，一个 PR 只做一件事。分支名说明用途。
- [ ] 整理（重命名、搬代码、格式）和行为改动分开提交，审查者可以分开看。
- [ ] 临时文件放会话的临时目录（scratchpad），不写进仓库；shell 脚本用 LF 换行。
- [ ] 新建 worktree 放主检出的同级目录，命名 `<仓库名>-<用途>`（项目约定另有规定的照它）；用完先拆里面的链接（junction / 符号链接，只删链接），再 `git worktree remove`，确认目录真的没了。
- [ ] 起的 dev server、后台进程用完就关。
- [ ] 交付说明：改了什么、怎么验证的（命令和结果）、没验证什么、剩余风险、用户怎么试。

## 不做

- 不推送受保护分支、不合并、不部署、不发版、不对外发消息、不动生产数据：一律先问用户。
- 不给自己的交付做验收：交给 `team-reviewer`。

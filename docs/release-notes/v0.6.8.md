这一版只做一件事，但它比看上去大：让「切换账号」真的算数。此前切完账号，正在跑的会话不会跟着换，得手动结束再恢复；而 kimi 更彻底——它的多账号从来就没有隔离过，几个账号一直共用同一个目录。

## 切账号即时生效

- **运行中的会话可以一起切过去**：账号是靠启动时注入的环境变量生效的，进程中途换不了。此前只能手动「结束会话 → 恢复」，现在切完会问一句，点头就替你把该 Agent 运行中的会话就地重启到新账号，对话内容保留
- 先切设置、再问要不要重启：不点头就是原来的行为（账号已切，运行中的会话留在原账号），而不是连账号都切不成
- 待重启的会话数由后端给，不再自己翻看板列表数——那份列表分页，连着但久未活动的会话会被漏掉，于是不弹确认也不重启，账号切了会话却还挂在旧账号上

## kimi：多账号此前根本没隔离

- **所有 kimi 账号一直共用 `~/.kimi-code`**：我们注入的 `KIMI_SHARE_DIR` 在 kimi-code 0.40 里是「旧版 kimi-cli 的迁移来源目录」，不是数据目录——它读的是 `KIMI_CODE_HOME`。于是凭据互相覆盖、会话历史混在一起，连预写目录信任与会话记录查找也一并落空，而且全程没有任何报错
- 本版改注入 `KIMI_CODE_HOME`，账号从此真正各写各的
- **升级后请留意**：此前建的 kimi 账号目录里本来就没有过数据（都写进了默认目录），升级后它们会显示「未登录」，重新登录即可；之前的会话与凭据都还在，归在默认账号名下

## 跨账号继续旧会话：扩到 codex 与 kimi

- 切账号后恢复旧会话，此前只有 Claude Code 能把会话带到新账号继续，codex 与 kimi 会退回会话原本的账号。本版两家都支持了，各自的会话文件协议都经真机验证后才声明
- opencode 的会话存储尚未取证，仍保持各账号独立——没验证过就搬运，只会造出一份它自己读不全的副本
- 顺带修好 codex 与 kimi 在多账号下的会话定位：此前只查默认目录，账号里的会话上下文、切换引擎、跨账号搬迁会全部静默失效

## 底盘

- 预写目录信任改用「不存在才写」，并发预写不再盖掉已有记录
- 新增三条不变量绊线：账号注入的目录变量必须与检测侧读的一致、会话目录不得跑到数据根之外、跨账号迁移的覆盖面钉成矩阵——这三类问题的共同点是出错时零报错，只能靠测试拦

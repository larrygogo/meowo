这一版主要让对话窗在五家 Provider 上表现一致：状态只有一种说法，提问和审批共用一种卡片，工具调用的样子也一样，运行状态不再和实际不符。Lead 现在可以用在 Codex、Kimi、Gemini、OpenCode 上，验收时签下的就是你看到的内容。另外，手机上能切换账号、查看用量，Windows 上又能把文件直接拖进输入框。

## 对话窗五家统一

- 状态词收成一张表：侧栏、灵动岛、消息气泡、通知、手机页里，同一个状态只用一个词
- 五家的提问卡和审批卡统一成一种：标题、按钮、键盘操作都一样，桌面和手机都能作答
- 工具调用按读、写、改、命令、搜索、网页、子任务分类显示，失败标红。Codex 的调用显示实际执行的命令，Gemini 的读写改不再归进「其他」，Codex 和 Gemini 也显示 diff 和增删行数
- 一直没有结果的调用，回合结束后显示「已中断」，不再一直计时
- 当前做不到的操作：能稍后执行的就排队，并写明会在什么时候执行；做不到的按钮置灰，并写明原因。不会再出现能点、点了才报错的情况
- Codex 可以在对话窗里切思考档
- 提问卡的「其他」改为「以上都不合适，我自己写回答」

## 送达与运行状态

- Kimi 运行中发的消息不再误报「未确认送达」。只要终端画面显示消息已经收下，就会改成已送达
- 「未确认送达」的消息不再给「重发」，改为「放回输入框」，避免同一条消息发两遍
- 在终端里连发两条相同的消息，对话页也显示两条
- 只剩后台 Bash 在跑时，会话不再显示「工作中」
- 后台任务被结束或停止时显示「已中断」，停靠栏不再一直显示「运行中」
- Kimi 回合结束后会话不再一直显示「工作中」，后台子代理完成后也不再显示进行中
- 投递卡住的消息可以隐藏，并放回输入框

## Lead

- Codex、Kimi、Gemini、OpenCode 都能用 Lead，并保留官方 TUI。在手机上回答关卡后，托管会话会自动继续
- 签验收时，签下的是当时看到的验收项和版本。每一项都能查到验证证据，重复提交同一份答复不会扩大签字范围
- 只差实测的验收项单独标出「待实测」，并提醒 agent 马上发验收关卡，不留到最后一起发
- 等后台子代理的时候不再被反复拦下
- 关卡卡片和 Lead 面板重做：标题直接说明要做什么，确认和验收点一下就能提交，面板显示任务进行到了哪一步
- 同一个项目开多个会话时，关卡答复只送到对应的会话

## 手机

- 可以查看多个账号，并在账号之间切换，额度用完不用回电脑
- 可以查看各 Provider 的用量
- 排队的消息可以用手指拖动排序
- 确认框改用应用内的样式

## 其他改进

- Windows 上又能把文件直接拖进对话窗的输入框
- Kimi 读到它的接口不接受的图片时会提前拦下，不会让整个会话卡住。请求被拒后可以撤回到出错前
- 改动卡里的文件可以展开，查看这一轮对它的每一次修改
- 「更改」面板列出本会话建过、动过的 PR，已合并和已关闭的可以收起
- 面板浏览器支持人工接管和交还，Claude、Kimi、Codex 回复里的截图有缩略图，可以点开看大图
- 新加的账号也能用你自己装的 skill 和 Lead
- 有会话正在启动时切换账号，不再报错
- Kimi 新会话的第一条消息能正常发出
- Windows 11 深色模式下窗口底色不再发灰，也不会被壁纸染黄
- CLI 升级后照常能用。对话页可以给 Codex、Gemini、OpenCode 的原生会话发消息
- 标题栏放不下时，先收起分支名和 PR 状态，会话标题最后才省略
- 界面缩放后，「更改」和「文件」页签里的按钮、行高也跟着放大

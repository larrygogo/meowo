这一版把「更改」面板改成了 VS Code 源代码管理的样子：能暂存、提交、放弃，会话开在项目主目录、agent 在 worktree 里改代码时也看得到改了什么。另外加了 Lead 工作流第一期，灵动岛的会话图标能看出运行、待处理和出错，提问卡不再 5 分钟就过期。

## 「更改」面板

- 顶部是「存储库」列表：仓库名、分支、有没有未提交的改动、领先和落后远程几个提交。点选一个仓库，下面是它的提交框、「暂存的更改」「更改」，最下面是折叠的「本分支已提交（未合入 main）」
- 文件行显示文件名、灰色的目录、增删行数和状态字母（M/A/D/U，有冲突是 !）。悬停出现打开文件、放弃更改、暂存或取消暂存，分组标题上有全部暂存、全部取消暂存、全部放弃
- 写好提交信息按 Ctrl+Enter 提交。没有暂存的更改时按钮是「提交全部」，会提交列表里显示的全部文件
- 放弃之前一律弹确认，写明是哪个仓库、哪些文件
- 开着搜索或「本会话 / 本轮」筛选时，整组操作只作用于看得见的文件。筛选藏起了会被提交的文件时不能提交
- 有合并冲突的文件不能暂存、放弃和提交，要先在终端或编辑器里解决
- agent 正在跑 git、提交钩子失败、没配 git 用户名和邮箱时，都会说明原因
- 手机远程页也能暂存、提交和放弃，只对和会话相关的仓库生效

## 多仓库和 worktree

- 会话开在项目主目录、agent 在 worktree 里改代码时，那个 worktree 会出现在存储库列表里。agent 只用命令在里面干活（`cd`、`git -C`、`git worktree add`）也认得出，绝对路径、相对路径和 Git Bash 的 `/c/…` 写法都认
- 主目录本身不是仓库、下面放着前后端几个仓库时也能用。主目录下两层以内的仓库和它们各自的 worktree 都认得出
- 只列本会话用过的仓库。会话还没用过任何仓库时，列出主目录下所有有未提交改动的仓库
- 仓库多时只给选中的那个算增删行数和已提交内容，其余的点到时再加载
- 「文件」页签顶上可以在工作目录和用过的 worktree 之间切换，和「更改」选中的是同一个

## Lead 工作流（第一期）

- 设置里可以把 Lead 工作流安装到 Claude Code，也可以卸载
- 对话窗底部多了 Lead 入口，能看任务的规格、验收进度和最近的记录。任务只在认领它的会话里显示
- agent 在关卡处等你拍板时出现关卡卡片，桌面和手机都能作答

## 灵动岛

- 会话图标的外圈：运行中旋转，等你处理时变黄，出错时变红

## 对话窗

- 新建会话页可以粘贴图片。发出的第一句话先显示在对话里，再在后台发进终端，发不出去时放回输入框
- agent 的提问卡不再倒计时，也不再 5 分钟后过期。随时可以按「去终端页」交还给终端
- 侧栏的工作区可以「从列表中移除」。只是不显示，文件夹和会话都不动，之后在这里新建会话会自动回来
- 已完成的会话可以顺手删掉它建的 worktree

## 修复

- 新建会话页发出的第一句话，在 agent 跑了十几步之后会再挂一条「未确认送达」。现在只显示一条
- 新建会话页发出的消息有时一直停在「发送中」
- 在会话里跑测试会把会话自己的终端换绑走，对话页显示成「外部」会话
- 新建会话页挂着上一个会话的右侧面板
- 同一个项目里，别的会话也显示这个会话的 Lead 面板
- Lead 面板一直停在旧任务上，看着像更新很慢。现在优先显示本会话认领的最新任务
